Estimate

Know the state you cannot measure directly

control.kalman · read the module

Estimators that turn noisy sensor readings into a state estimate and its uncertainty. Every update returns the innovation and its covariance, so you can compute the normalised innovation squared (NIS) and notice when the filter stops agreeing with the data.

  • (F, H, Q, R, x0, P0, B=None) class

    Linear estimator: the best guess of the state, and how unsure it is.

    What it does
    Tracks a state mean x and covariance P for a linear model. predict moves them forward one step; update folds in a measurement and returns the innovation y and its covariance S.
    Why it matters
    Every later decision trusts the estimate, so its stated uncertainty has to be honest. The covariance update uses the Joseph form and is re-symmetrised, which resists the rounding errors that can leave a covariance asymmetric or not positive semi-definite.
    Where it stops
    It does not raise an alarm when it is wrong. Compute NIS from the returned y and S and act when it leaves its expected range. Assumes the model and the noise levels are right.
    Read the source
  • (f, F_jac, h, H_jac, Q, R, x0, P0) class

    The same idea for nonlinear systems, linearised at every step.

    What it does
    Predicts with your function f and updates with your function h, using the Jacobians F_jac and H_jac you supply to carry the covariance.
    Why it matters
    Real plants are nonlinear. Because the Jacobians are explicit inputs, they can be reviewed and tested on their own instead of hiding inside a solver.
    Where it stops
    Linearisation error is not tracked. With strong nonlinearity or a poor starting estimate it can become overconfident, and a wrong Jacobian gives wrong answers without any error. Check your Jacobians against finite differences.
    Read the source
  • (f, h, Q, R, x0, P0, alpha=0.001, beta=2.0, kappa=0.0) class

    A nonlinear estimator that needs no Jacobians.

    What it does
    Pushes a small set of sigma points through f and h and rebuilds the mean and covariance from them (scaled unscented transform, additive noise). alpha, beta and kappa set the spread.
    Why it matters
    Removes a class of mistakes: there is no hand-derived Jacobian to get wrong. A better fit when the nonlinearity is strong or the derivatives are tedious.
    Where it stops
    Still a Gaussian approximation, with additive noise only. The covariance must stay positive definite: if it does not, the Cholesky step raises an error, which is deliberate.
    Read the source
Try it
import numpy as np
from control import KalmanFilter

# Position and velocity, with position measured once per step.
dt = 0.1
kf = KalmanFilter(F=[[1, dt], [0, 1]], H=[[1, 0]], Q=0.01 * np.eye(2),
                  R=[[0.25]], x0=[0, 0], P0=np.eye(2))
kf.predict()
y, S = kf.update([0.3])
nis = float(y @ np.linalg.solve(S, y))   # normalised innovation squared
print(round(nis, 3), nis < 6.63)         # 6.63 = 99% chi-square gate, 1 degree of freedom

Prints:

0.071 True

Certify

Show the system settles, or find where it does not

control.lyapunov · read the module

Tools for the question "does it settle?" A Lyapunov function is a measure of distance from the safe state that must shrink along every trajectory. If you can write one down and check it, you have a reason to expect recovery, not just a plot where it happened to recover.

  • (A) function

    Yes or no: do small disturbances to a linear system die out?

    What it does
    True when every eigenvalue of A has a strictly negative real part.
    Why it matters
    The cheapest first test of a linearised system, and the precondition for the Lyapunov equation below.
    Where it stops
    A bare yes or no with no margin: an eigenvalue at -1e-12 passes. It says nothing about large disturbances, or about a nonlinear system far from the point you linearised at.
    Read the source
  • (A, Q) function

    Builds a stability certificate for a linear system.

    What it does
    Solves AᵀP + PA = -Q. For Hurwitz A and Q > 0, V(x) = xᵀPx is a Lyapunov function for x' = Ax. Raises ValueError if A is not Hurwitz.
    Why it matters
    Turns "it looks stable" into a function you can check. Refusing to answer for an unstable A is deliberate: no false certificate.
    Where it stops
    A certificate for the linear model only. Q is yours to choose and is not checked to be positive definite. How far the certificate reaches on the real nonlinear plant is a separate question.
    Read the source
  • (A, B, Q, R) function

    A stabilising feedback gain, with its certificate attached.

    What it does
    Continuous-time LQR. Returns the gain K (control u = -Kx) and the Riccati solution P, where V(x) = xᵀPx is a Lyapunov function of the closed loop.
    Why it matters
    Q and R state in plain numbers what you penalise: state error against actuator effort. You get a gain you can inspect, and a Lyapunov function with it.
    Where it stops
    Linear model, no actuator limits. Saturation can break the guarantee, so re-check with the limits in the loop (see tanh_sat). SciPy raises an error if it cannot solve the Riccati equation, for example when the system is not stabilisable.
    Read the source
  • (f, V_grad, samples, tol=1e-09) function

    Try to break a stability claim by sampling.

    What it does
    Evaluates V̇ = ∇V · f at each sample point (skipping the origin) and returns (ok, worst_value, worst_point).
    Why it matters
    A cheap, honest way to attack a Lyapunov argument. If the claim is wrong this tends to find where, and it names the worst point so you can look at it.
    Where it stops
    Falsification, not proof. Passing means no violation was found at the points you sampled, and nothing more. Sample near the edge of the region you care about.
    Read the source
  • (m=1.0, l=1.0, g=9.81, k=2.0, u_max=3.0, catch_angle=0.35, blend_width=0.0) class

    A worked hybrid controller: pump energy, then catch with LQR.

    What it does
    A torque-limited pendulum. An energy-pumping law swings it up, then hands over to LQR near upright. With blend_width = 0 the hand-over is a hard switch and the torque limit is a clip; with blend_width > 0 both become smooth. simulate runs it with RK4.
    Why it matters
    Shows the two classic sources of jumps in a controller, the mode switch and the clip, next to their smooth fix, on a system small enough to read and test.
    Where it stops
    A teaching and benchmark system. It makes no claim to model any real hardware.
    Read the source
Try it
import numpy as np
from control import is_hurwitz, lyapunov_equation, check_vdot_negative

A = np.array([[0.0, 1.0], [-2.0, -3.0]])
print(is_hurwitz(A))
P = lyapunov_equation(A, np.eye(2))                    # V(x) = x' P x
samples = np.random.default_rng(0).normal(size=(500, 2))
ok, worst, at = check_vdot_negative(lambda x: A @ x, lambda x: 2 * P @ x, samples)
print(ok, worst < 0)   # "no violation found in these samples", not a proof

Orient

Rotations without the usual traps

control.so3 · read the module

Orientation as 3×3 rotation matrices: no gimbal lock as with Euler angles, no double cover as with quaternions. These are the shared building blocks of the geometric controllers.

  • (w) function

    Turns a 3-vector into the matrix that does a cross product.

    What it does
    Maps w to the skew-symmetric matrix with hat(w) @ v == cross(w, v).
    Why it matters
    The basic translation between angular velocities and rotation matrices. The rotation code in the suite builds on it.
    Read the source
  • (W) function

    The inverse of hat.

    What it does
    Reads the 3-vector back out of a skew-symmetric matrix.
    Why it matters
    Lets an error measured as a matrix, such as RdᵀR - RᵀRd, become a vector that can drive a torque command.
    Where it stops
    It reads the entries without checking that the matrix really is skew-symmetric.
    Read the source
  • (w) function

    Rotation vector in, valid rotation matrix out.

    What it does
    Rodrigues' formula: the exponential of hat(w), with a series for tiny angles so it never divides by zero.
    Why it matters
    Advancing an orientation by multiplying exponentials keeps it a rotation. Integrating matrix entries directly lets it drift off the rotation group.
    Where it stops
    Rounding still accumulates over millions of steps. In long runs, check control.so3.is_rotation now and then.
    Read the source
  • (R) function

    Rotation matrix in, "how far and about which axis" out.

    What it does
    Principal logarithm. Returns the rotation vector, with norm in [0, π], and handles the cases near 0 and near π where the textbook formula divides by zero.
    Why it matters
    A well-defined orientation-error vector, whose norm is the angle, is what attitude monitors and controllers need.
    Where it stops
    Assumes the input is a rotation matrix and does not check. At exactly 180° the sign of the axis is arbitrary.
    Read the source
Try it
import numpy as np
from control import exp_so3, log_so3

R = exp_so3([0.0, 0.0, np.pi / 2])               # 90 degrees about z
print(round(float(np.linalg.norm(log_so3(R))), 6))   # the angle, recovered

Prints:

1.570796

Command

Steer attitude and position on rotation matrices

control.geometric · read the module

Controllers that work directly on rotation matrices (Lee, Leok and McClamroch, CDC 2010), which avoids the singularities of Euler angles and the unwinding of quaternions.

  • (J, kR=8.0, kW=2.5) class

    Steers a rigid body's orientation to a target, from almost any start.

    What it does
    Tracking controller on SO(3) for J w' = M - w × Jw. moment returns the torque from the attitude and rate errors, step_dynamics advances the body on the group, and simulate runs the closed loop. The error function Ψ = ½ tr(I - RdᵀR) is a Lyapunov function.
    Why it matters
    The loop converges from every initial attitude except a measure-zero set where the error is exactly 180°. The guarantee names its own exception, so you know what is and is not covered.
    Where it stops
    The returned torque is not limited, so add saturation and re-test. Assumes the inertia J is known. The default gains are examples; choose them for your own inertia.
    Read the source
  • (mass, J, kx=8.0, kv=4.0, kR=8.81, kW=2.54, g=9.81, thrust_eps=0.02, heading='tilt_twist') class

    Holds a quadrotor at a target position, or moves it slowly to one.

    What it does
    The outer loop turns position and velocity error into a thrust vector, which fixes the desired attitude; the inner loop is GeometricAttitudeController. control returns thrust, torque and desired attitude; simulate runs it.
    Why it matters
    The paper's construction of the desired attitude has two singular points where the command jumps. The defaults (thrust_eps, heading="tilt_twist") keep it a valid rotation and move the singularity to downward-thrust commands, outside normal flight.
    Where it stops
    Omits the desired angular velocity and acceleration, so it suits slowly varying references only. Stability of the smoothed default is checked in simulation, not proven. Pass thrust_eps=0, heading="projection" for the paper's exact construction.
    Read the source
Try it
import numpy as np
from control import GeometricAttitudeController, exp_so3

ctrl = GeometricAttitudeController(np.diag([0.02, 0.02, 0.04]))
R0 = exp_so3([0.0, 0.0, 3.0])             # about 172 degrees away from the target
R, W, log = ctrl.simulate(R0, np.zeros(3), np.eye(3), T=6.0)
print(round(float(log[0, 1]), 2), float(log[-1, 1]) < 1e-6)   # error Psi: start, then ~0

Prints:

1.99 True

Bound

Remove the kinks, keep the limits

control.smooth · read the module

Every function here is C-infinity and has a width (eps, width or r). A smaller width follows the original more closely but makes derivatives larger and the problem stiffer. The width is a design choice, and each entry says how far the result can stray from the original.

  • (x, eps) function

    |x| without the corner.

    What it does
    √(x² + eps²) - eps. Zero at 0, and 0 ≤ |x| - value ≤ eps.
    Why it matters
    Solvers and gradient-based tools stumble where |x| has no slope. This is differentiable everywhere, and its distance from |x| is bounded by a number you choose.
    Where it stops
    The error budget eps is yours to set and to check against your tolerances.
    Read the source
  • (x, eps) function

    sign(x) without the instant flip.

    What it does
    x / √(x² + eps²), the derivative of smooth_abs. Tends to sign(x) as eps → 0.
    Why it matters
    A hard sign flips between -1 and +1 in zero time, which makes actuators chatter. This ramps across a band about eps wide.
    Where it stops
    Not ±1 inside the band. The band width trades chatter against stiffness.
    Read the source
  • (v, eps) function

    v / |v| that stays defined at zero.

    What it does
    v / √(|v|² + eps²).
    Why it matters
    Normalising a zero vector divides by zero at the worst moment, when the error reaches zero. This stays finite there.
    Where it stops
    The result is slightly shorter than a unit vector, so do not use it where exact unit length is required. The quadrotor controller uses a different fix for that reason.
    Read the source
  • (x, eps) function

    max(x, 0) with a smooth knee.

    What it does
    eps · ln(1 + e^(x/eps)). Never below max(x, 0) and at most eps · ln 2 above it.
    Why it matters
    Lets you penalise only the part of a quantity that exceeds a limit, without a corner at the limit. It errs towards penalising more.
    Where it stops
    A small penalty remains even below the limit, up to about 0.69 · eps.
    Read the source
  • (values, eps, axis=-1) function

    Largest of a list, smoothly, and never understated.

    What it does
    Log-sum-exp: max ≤ value ≤ max + eps · ln n for n values.
    Why it matters
    For worst-case readings, such as the hottest of several sensors. It can overstate the worst case slightly, but never understates it.
    Where it stops
    Overstates by up to eps · ln n, which grows slowly with the number of values.
    Read the source
  • (values, eps, axis=-1) function

    Smallest of a list, smoothly, and never overstated.

    What it does
    -smooth_max(-values), so min - eps · ln n ≤ value ≤ min.
    Why it matters
    For the smallest margin to a limit. It can understate how much margin is left, but never overstates it.
    Where it stops
    Understates by up to eps · ln n.
    Read the source
  • (x, limit, slope=1.0) function

    A command limit that is smooth and cannot be exceeded.

    What it does
    limit · tanh(slope · x / limit). The output stays inside ±limit, with gain slope near zero.
    Why it matters
    A hard clip has corners. This has none, and the bound still holds for any input, however large.
    Where it stops
    Approaches the limit but never reaches it, so the last few per cent of actuator range goes unused. Saturation can change closed-loop stability, so re-test with it in the loop.
    Read the source
  • (s) function

    A perfectly smooth 0-to-1 ramp.

    What it does
    0 for s ≤ 0, 1 for s ≥ 1, strictly increasing between. All derivatives vanish at both ends.
    Why it matters
    The building block for blending two behaviours. Outside the ramp you get exactly the old behaviour, with no residue.
    Where it stops
    A narrow ramp is steep in the middle, which makes derivatives large.
    Read the source
  • (s, low, high, a, b) function

    Hand over smoothly from one behaviour to another.

    What it does
    Blends a into b as the monitored value s crosses [low, high]: exactly a below low, exactly b above high.
    Why it matters
    Mode changes are where hard switches shock actuators. For control-affine systems with a shared Lyapunov function V, V̇ is affine in u, so if both a and b satisfy V̇ ≤ -γV, every blend does too.
    Where it stops
    That guarantee needs control-affine dynamics, a shared V, and the decrease condition for both laws. If any one fails, the blend carries no guarantee.
    Read the source
  • (u, u_max, r=1.0) function

    An actuator limit written as a smooth cost.

    What it does
    A strictly convex cost for the box |u| ≤ u_max: about r u² / 2 near zero, finite at the limit with infinite slope there.
    Why it matters
    Puts the limit in the cost instead of in a clip, so Pontryagin's principle still applies to the smoothed problem (see PMPShooting).
    Where it stops
    The shape depends on r. As r → 0 the optimum approaches bang-bang, with the stiffness that brings.
    Read the source
  • (g, u_max, r=1.0) function

    The best command under that cost, and it respects the limit.

    What it does
    argmin_u [w(u) + g·u] = -u_max · tanh(g / (r · u_max)), where w is barrier_cost.
    Why it matters
    A closed-form law that is smooth in g and never leaves the box.
    Where it stops
    Correct only for barrier_cost; a different cost has a different minimiser. Like tanh_sat, it never reaches the limit exactly.
    Read the source
  • (margins, eps) function

    Safety monitor, "is every margin positive?", that errs towards caution.

    What it does
    Smooth robustness of "always h ≥ 0" over samples: a soft minimum, which is never above the true minimum.
    Why it matters
    Sound by construction: a non-negative result means every sampled margin is non-negative. It can raise a false alarm, but it cannot certify a violated margin as safe.
    Where it stops
    Conservative by up to eps · ln n. Only as trustworthy as the margins fed in (sensors, model), and it checks sampled instants only, nothing between them.
    Read the source
  • (margins, eps) function

    Monitor, "did it reach the goal at least once?"

    What it does
    Smooth robustness of "eventually h ≥ 0": a soft maximum, which is never below the true maximum.
    Why it matters
    For recovery-type checks, such as "pressure returned to range at some point".
    Where it stops
    Optimistic, the opposite of smooth_always: a slightly positive value can occur when the best margin was actually negative, by up to eps · ln n. Require a margin above that before trusting it.
    Read the source
Try it
import numpy as np
from control import tanh_sat, smooth_always, smooth_eventually

cmd = np.array([-50.0, -1.0, 0.0, 1.0, 50.0])
print(float(np.abs(tanh_sat(cmd, limit=5.0)).max()) <= 5.0)    # bounded for any input

margins = np.array([0.9, 0.4, 0.05])           # distance to a limit at each sample
print(round(float(smooth_always(margins, 0.01)), 4))           # never above min(margins)

# smooth_eventually errs the other way: the best margin here is -0.002 (a miss),
# yet the soft maximum is positive. Demand a margin larger than eps * ln n.
print(round(float(smooth_eventually(np.array([-0.002, -0.004]), 0.01)), 4))

True
0.05
0.004

Watch

Find the jumps your logs already contain

control.continuity · read the module

Hard switches, clipping, thresholds and angle wrapping leave jumps and kinks in logged signals. This finds them in data you already have, so they can be replaced with the smooth versions above.

  • (t, y, window=7, ratio=8.0, abs_tol=1e-09) function

    Scan a logged signal for jumps and kinks.

    What it does
    Locates jumps in value (order 0) and kinks in slope (order 1) in a sampled signal y(t) and returns a list of Break records.
    Why it matters
    Discontinuities are where actuators get shocked and where models stop being valid. This points to the exact sample and time, so you can find the cause.
    Where it stops
    A heuristic: it compares each step with the median of its neighbours. Assumes near-uniform sampling. Rounded corners many samples wide are not reported. For noisy data, raise abs_tol to a few noise sigmas. A clean result is not a proof of smoothness.
    Read the source
  • (index, time, order, size) class

    The record find_breaks returns.

    What it does
    A frozen dataclass with index, time, order (0 = jump, 1 = kink) and size (the signed jump height or slope change).
    Why it matters
    A plain record you can log, assert on or alarm on.
    Read the source
Try it
import numpy as np
from control import find_breaks

t = np.linspace(0, 10, 1001)
y = np.sin(t)
y[600:] += 0.5                    # a hidden step at t = 6.0
for b in find_breaks(t, y):
    print(b.order, round(b.time, 2), round(b.size, 2))     # order 0 = jump

Prints:

0 6.0 0.51

Plan

Optimal manoeuvres, with the conditions written down

control.pmp · read the module

Pontryagin's minimum principle turns "find the best manoeuvre" into conditions the best manoeuvre must satisfy. Solving them gives a trajectory and the costate behind it, so you can check the optimality conditions instead of trusting a black-box optimiser.

  • (f, L, u_star, n_state, H_x=None, fd_step=1e-06) class

    Plan an optimal manoeuvre by solving its necessary conditions.

    What it does
    Indirect shooting in Euclidean state space. Given dynamics f, running cost L and the minimiser u_star, solve finds the initial costate (and the final time, if free) that meets the terminal conditions. continuation re-solves while a smoothing width shrinks, warm-starting each solve.
    Why it matters
    It fails loudly. If the terminal residual is above 1e-6 it raises RuntimeError instead of returning a nearby, wrong trajectory.
    Where it stops
    Normal extremals only, a costate guess is needed, and there is no second-order (conjugate-point) test. A solution is a stationary candidate, not a proven global optimum. Kinks in u_star make shooting hard; use barrier_control.
    Read the source
  • (t, x, lam, u, H, cost, T, lam0, residual, dense) class

    What PMPShooting.solve returns.

    What it does
    A dataclass holding t, x, lam, u, the Hamiltonian H, the cost, the final time T, the initial costate lam0, the terminal residual and a dense output.
    Why it matters
    Carries two self-checks: H must stay constant along an autonomous extremal, and residual says how well the terminal conditions were met.
    Read the source
Try it
import numpy as np
from control import PMPShooting

# Minimum-energy, rest-to-rest move of a double integrator: x'' = u, cost = integral of u^2 / 2.
f = lambda x, u: np.array([x[1], u[0]])
L = lambda x, u: 0.5 * float(u @ u)
u_star = lambda x, lam: np.array([-lam[1]])            # argmin of the Hamiltonian
ext = PMPShooting(f, L, u_star, n_state=2).solve(x0=[0, 0], T=1.0, lam0=[0, 0], x_T=[1, 0])
print(round(ext.cost, 4), ext.residual < 1e-6)         # closed form: 6

Prints:

6.0 True

Plan

Optimal rotation of a rigid body, without leaving SO(3)

control.geometric_pmp · read the module

The same principle for a rigid body's orientation. The group part is reduced analytically (Lie-Poisson), so only nine equations are integrated and the rotation is rebuilt on the group afterwards.

  • (J, u_max=None, r=1.0, time_weight=0.0) class

    Plan an optimal rotation of a rigid body, torque limits included.

    What it does
    Geometric PMP on SO(3) × ℝ³. solve(R0, RT, T) finds the extremal from rest to rest by default. u_max adds a smooth torque bound, and free_time=True with time_weight > 0 also solves for the time. control_at gives the torque at any time.
    Why it matters
    For reorienting a spacecraft or any rigid platform with torque strictly inside its bounds. No Euler angles and no quaternion normalisation, so the rotation never leaves SO(3).
    Where it stops
    First-order optimal only. Large rotations may need angle_steps > 1 or continuation in r. Raises RuntimeError if shooting fails, and ValueError for free_time without a time penalty.
    Read the source
  • (t, R, W, Pi, p, u, H, cost, Pi0, p0, residual, dense) class

    What AttitudePMP.solve returns.

    What it does
    A dataclass with the time grid, rotations R, rates W, costates Pi and p, torque u, Hamiltonian H, cost and terminal residual.
    Why it matters
    Same self-checks as Extremal: a constant H and a small residual.
    Read the source
  • (R0, W_of_t, T, steps=200) function

    Integrate an angular-velocity history into an orientation, without drift.

    What it does
    Solves R' = R hat(W(t)) with fourth-order Magnus steps. Each step is a rotation, so R stays on SO(3) to machine precision.
    Why it matters
    Integrating rotation matrices with a generic ODE solver lets them drift off the rotation group. This keeps them rotations.
    Where it stops
    W_of_t must return shape (3, len(times)). Accuracy is fourth order in the step size and depends on how smooth W is.
    Read the source
Try it
import numpy as np
from control import AttitudePMP, exp_so3

pmp = AttitudePMP(np.diag([1.0, 2.0, 3.0]))
ext = pmp.solve(np.eye(3), exp_so3([0.0, 0.0, 1.0]), T=2.0)    # rest to rest, 1 rad about z
print(ext.residual < 1e-6, float(np.ptp(ext.H)) < 1e-6)        # met the target; H constant

True True
